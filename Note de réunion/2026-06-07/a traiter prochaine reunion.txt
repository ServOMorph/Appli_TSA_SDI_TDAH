## Usage réel de l'énergie dans l'appli

Constat (test manuel V2-10, 2026-07-06) : le champ "Énergie" (anciennement "Souffle") est actuellement purement décoratif.

État actuel du code :
- Une seule valeur par jour (`todayEnergy` / `todayEnergyStatus`), stockée via `saveTodayEnergy` (`AppContext.tsx`)
- Chaque nouvelle saisie écrase la précédente (pas d'historique)
- Affichée uniquement dans le chip de la TopBar
- Aucun autre effet dans l'application : pas de lien avec le mode surcharge, pas de filtrage des tâches, pas d'historique consultable

Question ouverte pour Marie : à quoi doit servir concrètement l'énergie dans son usage quotidien ?
Pistes possibles à valider avec elle (aucune tranchée pour l'instant) :
- Rester purement informatif (aucun changement)
- Lien avec le mode surcharge (énergie basse → suggestion ou activation automatique du mode surcharge)
- Historiser les saisies (plusieurs check-in par jour, consultables) sans effet fonctionnel supplémentaire
- Autre usage à définir selon son ressenti réel de la fatigue/surcharge dans une journée

Cette décision bloque la finalisation de la Phase V2-10 (voir `roadmap_v2.md` § "Constats test manuel V2-10", sous-section "Décisions produit à prendre").
