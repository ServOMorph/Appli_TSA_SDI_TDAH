## 2. Refonte majeure — Système d'énergie « cuillères » + tâches obligatoires + surcharge automatique

C'est le cœur de la demande. Les trois éléments sont interdépendants et forment une seule fonctionnalité. État actuel du code : l'énergie est une valeur unique/jour purement décorative ; les tâches n'ont aucun coût d'énergie ; le champ `essential` (TaskV2) existe mais n'est relié à aucune UI ; le mode surcharge est un toggle 100 % manuel.

### E1 — [P1] Coût d'énergie par tâche à la planification — l.21-35, 62-88, 594
À l'ajout/planification d'une tâche, une fenêtre demande **combien d'énergie** la tâche va coûter, sur une échelle **1 à 12**. Sélection façon code Société Générale : les chiffres 1-12 s'affichent, on sélectionne (l.66-68). Nécessite un nouveau champ de coût d'énergie sur la tâche (absent du modèle actuel).

### E2 — [P1] Case « obligatoire » par tâche — l.50-88, 110-113, 603-605
Dans la même fenêtre, une case à cocher « obligatoire » (indépendante du coût d'énergie). Une tâche obligatoire (ex : McDo, rendez-vous) ne peut pas être repoussée par le mode surcharge. Débat sur l'ordre des deux champs (l.74-87) → conclusion : les deux présentés ensemble dans une fenêtre « symétrique » à deux carrés (un pour le chiffre d'énergie, un pour la case obligatoire). **Ce « obligatoire » correspond exactement au champ `essential` déjà présent dans le modèle TaskV2 mais jamais câblé.**

### E3 — [P1] Barème d'énergie personnel — l.520-535, 591-604
L'échelle est propre à chaque personne (pas de barème imposé par l'app). C'est l'utilisateur qui évalue son énergie du jour et le coût de chaque tâche selon son propre ressenti. Objectif thérapeutique assumé (l.533) : amener la personne à se poser des questions sur sa fatigabilité.

### E4 — [P1] Check-in énergie à chaque connexion — l.31-33, 181-183, 519, 525
À **chaque** ouverture de l'app, demander le niveau d'énergie du jour (1-12). **Constat code : ce check-in récurrent n'existe pas aujourd'hui** — l'énergie n'est demandée que pendant l'onboarding (`E03Energy`) ; à la reconnexion, `init()` route directement vers le dashboard. À construire.

### E5 — [P1] Mode surcharge AUTOMATIQUE — l.42-49, 515-595, 548-577
Le mode surcharge doit s'activer **automatiquement** quand la somme d'énergie des tâches planifiées restantes dépasse l'énergie du jour. Le bouton « Mode surcharge » en haut ne doit **plus** servir à l'activer manuellement (l.515-518, 567) :
- Il devient **informatif** : au clic, affiche un descriptif de ce qu'est le mode surcharge.
- Hors surcharge : une case grisée « Désactivé » (non cliquable pour activer — l.565-573).
- En surcharge : le bouton s'affiche en couleur, case « Activé » (l.558-576).
- Activation strictement automatique, non désactivable manuellement (l.567-570) : sinon ça biaise le principe (c'est l'énergie saisie qui pilote).

### E6 — [P1] Comportement en surcharge : grisé / reporter, obligatoires en couleur — l.46-47, 110-113, 578-589
Quand la surcharge est active :
- Les tâches dont le coût dépasse l'énergie restante s'**atténuent / grisent** mais restent **visibles** (l.46-47, 587). Ne pas les faire disparaître.
- Les tâches marquées **obligatoires** restent affichées normalement, en couleur pastel (l.585-587).
- Les non-obligatoires grisées, éventuellement avec un libellé « Reporter » (l.581-583) — c'est l'utilisateur qui décide de reporter ou non.
- Objectif (l.595-601) : au regard du planning, la couleur = « OK vas-y », le grisé = « attention, au-delà de ta limite ».

### E7 — [P2] Symbole d'énergie = cuillères (pas d'étoiles) — l.102-104, 128-134, 612-629
Marie rejette les étoiles (« ça ressemble trop à… »). Elle retient la théorie des **petites cuillères** (Christine Miserandino, l.620-627) : stock limité de cuillères d'énergie. L'unité d'énergie doit être représentée par des cuillères. Contrainte esthétique forte (l.131-134) : garder l'aspect **sobre, clean, non enfantin** de l'app actuelle. Raphael a carte blanche sur le visuel tant que ça reste sobre.

### E8 — [P2] Affichage du coût d'énergie sur le Planning — l.101-104
Quand une tâche est planifiée, afficher son coût d'énergie (en cuillères) sur la case du planning.

### E9 — [P3] Nombre de cuillères max configurable dans les paramètres — l.631-635
Permettre à la personne de définir son stock max de cuillères dans les paramètres (ex : autre que 12). Marie dit explicitement « ça on verra plus tard » → **reporté**.
